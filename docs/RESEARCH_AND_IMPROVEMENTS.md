# Research and implementation notes

Reviewed 6 October 2026. This project remains an academic scenario simulator.

## IEEE research reviewed

The accessible IEEE abstracts and indexed metadata informed the design. Full-text access was not available through the browsing tool; no claim is made that these papers were reproduced or that their reported performance transfers to Chennai.

1. [Flood Forecasting System Based on Integrated Big and Crowdsource Data by Using Machine Learning Techniques](https://ieeexplore.ieee.org/abstract/document/8949502), IEEE Access, 2020. DOI: 10.1109/ACCESS.2019.2963819. The abstract describes combining weather, hydrology, spatial and crowdsourced inputs. Application here: demand features include rainfall, depth, density and estimated vulnerability, with explicit provenance. The application does not currently have the paper's observed input streams.
2. [A Transformer-Based Probabilistic Deep Learning Framework for Uncertainty-Aware Long-Range Flood Forecasting Using Satellite-Derived Mesoscale Inputs](https://ieeexplore.ieee.org/abstract/document/11475459), IEEE JSTARS, 2026. DOI: 10.1109/JSTARS.2026.3681213. The abstract describes probabilistic forecasting from satellite inputs in US basins. Application here: report uncertainty and evaluate a held-out event. The portable demand model uses Extra Trees and split conformal calibration; it does not implement the paper's transformer or long-range flood forecast.

These references support data fusion and uncertainty-aware evaluation as design directions. The choice of a small tree ensemble is an engineering decision based on this project's tabular inputs and CPU runtime, not a result attributed to either paper.

## Implemented ML

- 48 Extra Trees regressors, maximum depth 8, minimum leaf size 12, fixed seed 42.
- Four features: rainfall, flood depth, population density and vulnerability. Per-person targets are scaled by shelter assignment count at inference. This avoids learning arbitrary absolute demand for large populations, and produces zero ML demand when the population is zero.
- Estimated density comes from the nearest modeled population cluster. Vulnerability uses a documented categorical mapping; it is not a measured feature. These approximations limit interpretation.
- Training/calibration partition excludes every 2023_Michaung row. Calibration is separate from fitting. The 2023 event is used only for evaluation.
- Split-conformal absolute residual quantiles use the finite sample correction at nominal 90% marginal coverage, separately for each resource. The underlying synthetic labels are noisy and event distributions differ. Neither simultaneous coverage nor real-world coverage is established.
- Point estimates and interval lower bounds enforce project planning minimums: 3 litres drinking water, 3 food units and 0.02 medical-kit units per person. These are simplified simulator quantities, not a complete humanitarian provision specification.
- Inputs outside training feature minima/maxima use rules. Missing files also use rules. The range check cannot detect every type of distribution shift.
- The JSON artifact contains tree arrays, feature ranges, dataset SHA-256, calibration radii and held-out metrics. Runtime inference imports no numerical or deep-learning libraries. The training script verifies portable predictions against scikit-learn.

## Backend correctness and performance

- Polygon depth checks now stop at the actual polygon boundary instead of also using the surrounding circle. Polygon visualization uses the same conservative uniform depth as routing.
- Zero-depth scenarios produce no flooded overlay or flooded-area metric. Timelines include the exact requested duration even when the time step does not divide it.
- Inundated shelters cannot accept road evacuation assignments. Unknown presets return a validation error. Preset rainfall levels use the same rates as the UI.
- A failed simulation restores the previous inventory. Stock and stale simulation-ID checks remain in place.
- Terrain interpolation uses a bounded cache. Truck, evacuation and amphibious graph creation reuse edge-depth computations for the same flood state. Changed flood states invalidate the cache.
- Evacuation uses one Dijkstra search per allocation chunk to reach all shelters. It repeats after congestion weights change rather than reusing stale paths.
- Fully supplied destinations skip unnecessary delivery planning. Legacy SHAP setup runs once and a missing explanation cannot invalidate inference; fabricated explanation percentages were removed.

- Completed runs open at peak population exposure. Chart buttons change the map and pause playback. Model name, provenance and prediction counts are visible.
- Same-origin Next.js API proxy avoids browser-to-port-8000 configuration problems, including access from another device.
- Manual allocation updates the timeline, exported inventory ledger and root delivery routes.
- 51 backend regression tests passed; 95 strict live API integration tests passed. Frontend production build, type check and lint passed.
- Desktop and 390px mobile screenshots were inspected. Mobile document width was exactly 390px; no horizontal overflow. Browser reported no page exceptions.
- Browser checks covered a real simulation through the proxy, chart/timeline selection, mobile resources navigation and successful manual supply allocation.

## Data needed for real forecasting

A future hydrology model needs observed rainfall/time series, water levels, terrain raster and drainage information, inundation observations, and event/location holdouts. Relief learning needs measured occupancy and consumption. Compare against persistence and physical baselines; assess extremes, calibration and distribution shifts before claiming operational accuracy. A temporal attention model becomes useful when these time-series inputs exist; adding it to generated labels would not resolve the missing evidence.

## 2026 Research Enhancements: Kaggle, IEEE & Open-Source Integration

### 1. Kaggle Chennai Water Management & Reservoir Hydrology Engine
Calibrated with empirical daily telemetry (inflow, outflow, storage, and rainfall records from 2015 to 2023) from the **Kaggle Chennai Water Management** dataset and Tamil Nadu Water Resources Department (WRD) dam safety standard operating procedures:
- **Chembarambakkam Lake**: Capacity 3,645 Mcft, FTL 85.40 ft, Catchment 358 sq km. Outflow governs the Adyar River corridor (Tiruneermalai, Anakaputhur, Saidapet, Kotturpuram, Adyar Estuary). Sluice gates: 19 gates, modeled with emergency surcharge release above 95% storage (historical 2015 benchmark: 29,400 cusecs).
- **Poondi Reservoir (Sathyamurthy Sagar)**: Capacity 3,231 Mcft, FTL 138.00 ft, Catchment 2,072 sq km. Primary River: Kosasthalaiyar River (Manali industrial corridor and Ennore Creek). Sluice gates: 16 gates.
- **Red Hills (Puzhal Lake)**: Capacity 3,300 Mcft, FTL 50.20 ft, Catchment 59 sq km. Primary River: Puzhal Surplus Channel / Captain Cotton Canal. Sluice gates: 6 gates.
- **Cholavaram Lake**: Capacity 1,081 Mcft, FTL 64.50 ft, Catchment 80 sq km. Sluice gates: 4 gates.

**Hydrological Physics Model**:
$$\text{Inflow} (Q) = C \cdot I \cdot A$$
Storage accumulation: $\Delta S = \text{Inflow} - \text{Discharge}$. Dynamic gate operation follows Tamil Nadu WRD Dam Safety rules:
- $< 70\%$ capacity: Ecological base release ($\le 150$ cusecs).
- $70\% - 85\%$ capacity: Precautionary buffer release.
- $85\% - 95\%$ capacity: Active flood cushion matching release.
- $> 95\%$ capacity: Emergency surcharge release up to maximum gate discharge.

**Downstream River Surge Modeling**:
Translates cusec discharge rates into urban river stage surges (projected water level rise in meters) and automated evacuation advisories for GCC Zones 1, 2, 3, 10, 12, and 13.

### 2. IEEE Literature Methodologies
- **IEEE Multi-Criteria Decision Making (MCDM) using TOPSIS**:
  Implemented in `backend/app/services/ai_advisor.py` to rank all 15 Greater Chennai Corporation zones across 5 conflicting criteria:
  1. Flood Inundation Depth (Benefit, weight 0.25)
  2. Stranded / Vulnerable Population (Benefit, weight 0.30)
  3. Road Inaccessibility / Isolation Score (Benefit, weight 0.20)
  4. Base Elevation Vulnerability (Cost, weight 0.15)
  5. Baseline Vulnerability Multiplier (Benefit, weight 0.10)
  Computes Euclidean separation distances to ideal ($A^+$) and negative-ideal ($A^-$) solutions and calculates relative closeness coefficients $C_i^* \in [0, 1]$, categorizing zones into:
  - `P1_IMMEDIATE_DISPATCH` ($C_i^* \ge 0.65$)
  - `P2_HIGH_PRIORITY` ($0.45 \le C_i^* < 0.65$)
  - `P3_MODERATE_STANDBY` ($0.25 \le C_i^* < 0.45$)
  - `P4_ROUTINE_MONITORING` ($C_i^* < 0.25$)
- **Height Above Nearest Drainage (HAND)**:
  Uses relative elevation differences from nearest drainage channels (Adyar, Cooum, Buckingham Canal, Kosasthalaiyar) to model pluvial and fluvial susceptibility.
- **Bureau of Public Roads (BPR) Volume-Delay Function**:
  $$t_e = t_0 \left[1 + \alpha \left(\frac{V_e}{C_e}\right)^\beta\right]$$
  Computes realistic evacuation traffic latency as evacuee headcounts converge toward accessible shelters.

### 3. Open-Source GitHub State-of-the-Art Adaptations
- **FloodNav**: Dynamic offline-first road graph pruning where road segments exceeding critical water depths (0.50m for pedestrians, 0.30m for supply trucks) are dynamically severed while preserving elevated flyover structures (Kathipara, Gemini, Koyambedu).
- **water-watch**: Real-time reservoir sensor threshold monitoring and early warning alerts.
- **Flood-Guard-AI**: Heterogeneous multi-modal fleet coordination (heavy 6x6 all-terrain trucks, amphibious boats, and helicopter airlift sorties).
